# OpenKubes Organization Profile

This repository maintains the public OpenKubes organization profile in
[`profile/README.md`](profile/README.md).

GitHub displays that file on the organization's Overview page after it is
merged into this public repository's default branch. Keep profile changes on a
focused branch and submit a pull request for human review. Do not merge or
publish profile changes automatically.

Follow [GitHub's organization profile conventions](https://docs.github.com/en/organizations/collaborating-with-groups-in-organizations/customizing-your-organizations-profile).
The logo is reused from the official `openkubes/openkubes` repository. Repository
descriptions should be checked against each repository's default-branch README.
The framework's [`NAMING.md`](https://github.com/openkubes/openkubes/blob/main/NAMING.md)
and committed ADRs define architectural terminology and boundaries.

Do not add organization-wide default community health files as part of this
profile change: they can affect other repositories that have no local override.

## Recommended public repository pins

Pins have not been changed by this pull request. An organization owner can
configure them manually:

1. Open [the OpenKubes organization](https://github.com/openkubes).
2. Select **View as: Public** if that selector is shown.
3. Choose **Customize pins** in the Pinned section, or **pin repositories** if
   no pins exist yet.
4. Select these six repositories, then choose **Save pins**:
   - [openkubes](https://github.com/openkubes/openkubes)
   - [ok-console](https://github.com/openkubes/ok-console)
   - [ok-cluster](https://github.com/openkubes/ok-cluster)
   - [ok-local](https://github.com/openkubes/ok-local)
   - [ok-storage](https://github.com/openkubes/ok-storage)
   - [ok-observability](https://github.com/openkubes/ok-observability)
5. Arrange them in the order above using GitHub's pin-reordering controls if
   available.

## Review checklist

- Verify the public repository inventory, including forks and this `.github`
  profile repository; include each repository once in the ecosystem overview.
- Check every repository description against its README and preserve maturity
  boundaries. Do not add unverified readiness or security claims.
- Verify links and the official logo URL. Review the rendered Markdown on both
  desktop and mobile widths.
- Keep all profile copy in English. Exclude secrets, internal infrastructure
  details and private links.
